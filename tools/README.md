# 渲染前的闸 —— 做视频 skill 的通用方法

这份文档是从一支片的四轮迭代里榨出来的（v1→v4，累计烧掉约两小时）。
它不绑定 handdrawn，**任何一条出片线都能照搬**。

---

## 一句话

> **验收要排在渲染前面。**
> 而绝大多数出片流程把它排在了后面 —— 这是「跑了二十多分钟才发现做坏了」的唯一原因。

`hyperframes snapshot` 吃的是**工程目录**，不是视频。建完帧就能抓图，**不必先渲**。
可默认流程是「建全部格 → 渲整片 → 抓中点 → 才看见不对」，于是每发现一个问题都要先付一次整片渲染。

把顺序倒过来，发现问题的时间从 20–26 分钟掉到 2–5 分钟：

```
旧：建 N 格 ─────────────────→ 渲整片 → 抓中点 → 发现不对 → 全部重来
新：建第 1 格 → 闸① → 停下等人（2 分钟，材质方向错就死在这儿）
    建其余格 → 闸② → 自己修（5 分钟，内容/时间轴错就死在这儿）
    ────────────────────────→ 渲整片（只渲这一次，且渲的是验过的）
```

---

## 四条通用规矩

### 1 · 抓三点，不抓中点

每格在 **30% / 50% / 85%** 各抓一帧。

只抓中点会漏掉一整类缺陷：元素进场后过早退场时，中点那一帧看着好好的，**格子后半段其实是空的**。
实测踩过 —— 七格里四格的主体在中点之后就没了，中点抓帧全部「正常」，
直到手工抓了 22.07s 和 29.69s 才看见画面是空的。

终点取 85% 而不是 100%：正终点常常已经在出场转场里，画面本来就该在退。

### 2 · 退出码不许过管道

```bash
node lint.mjs | tail -25      # ✗ 拿到的是 tail 的退出码，永远 0
```

这条最阴：执行方于是「报完成」，而闸实际是 1。**报喜不报忧比直接失败更贵**，因为你以为过了。

闸内部一律 `spawnSync` 直接拿 `status`，结论写进 `design/_gate/verdict.json`，
页面/复盘认这个文件，不认执行方的自述。

### 3 · 零样本不等于通过

一个闸如果可能因为「没找到东西可查」而返回 0，它就必须**把样本数打出来**。

实测最阴的一次：`gate.mjs` 调的通用 motion-lint 只从 `tools/` 和 `src/` 里找源码，
而这条出片线的帧是 `compositions/frames/*.html` —— 它一条都读不到，打印
「blur 0 处 / 缝 0 条」然后 exit 0。闸连报两次 ✓，而换成真读帧的那个 lint，
同一批帧里立刻抓出两处 30ms / 40ms 的错峰。

**判据①②当时是零样本。** 这比退出码被管道吃掉更难发现 —— 那个至少还打印了真结果。

→ 一条出片线至少要有一个**读得懂自己产物格式**的 lint。通用 lint 可以留，
   但别让它当唯一的那个。
→ 附带盲点：正则抓参数的 lint 通常**只认字面量**。`step: L.cmd ? 0.030 : 0.012`
   这种算出来的值它看不见 —— 算出来的值不等于查过了。

### 4 · 闸要判像素，不能只拍照

代码级的 lint（选卡纪律、动效尺度、渲染错误）**看不见画面**。
真正让人一眼说「这不对」的几件事只在像素里。`frame-audit.py` 目前判四条：

| 判据 | 阈值 | 抓的是什么 |
|---|---|---|
| 坠底 / 顶头 | 重心不在 30%–58% | 主体掉到画面下部，上方大片空 |
| 空帧 | 墨覆盖 < 0.5% | 转场缝里出现纯白，观感就是「卡了一下」 |
| 糊死 | 墨覆盖 > 60% | 转场把画面涂成一记闷棍 |
| 留白断层 | SAFE 内连续空带 > 25% | 画面从中间断成两截 |
| 缺字幕 | 字幕带墨 < 0.3% | 预留了字幕带却没人去画 |

**重心和空带只在每格「落定的那一帧」（85% 采样点）判** —— 动画演到一半时构图本来就是偏的，
不限定会误报。这个误报我自己踩过一次，一并修了。

## 用法

```bash
# 闸①：只建了第一格就跑，2 分钟回答「材质/字体/风格对不对」
node tools/gate.mjs . --stage 1 --spans 4.5,8.7,6.8,6.9,9.3,8.0,8.0

# 闸②：全部格建完、渲染之前跑
node tools/gate.mjs . --stage 2 --spans 4.5,8.7,6.8,6.9,9.3,8.0,8.0 --captions 1
```

退出码：`0` 过 / `1` 没过 / `2` 没法判（缺文件、命令跑不起来）。

**闸必须装在工程内**（`server.mjs` 的 `installGate` 每次开跑自动拷）。
放在工作台根、让执行方走 `../../tools/gate.mjs` 会被权限层挡掉 ——
而且是**静默**挡掉：片子照渲照交，只是没人验过。这个坑也踩过。

## 做新 skill 时怎么套

1. **先定版面三层**，写进 kit 而不是靠每张卡自觉：
   内容区 / 字幕带 / 平台 UI 区（竖屏底部约 14% 会被抖音小红书的按钮盖住，谁也不许进）。
2. **给「重心该落在哪」一个显式变量**（如 `S.hero`）。
   只给 safe area 是不够的 —— 贴着 safe 下沿放内容是合法的，但读起来像掉下去了。
3. **凡是 kit 预留了的东西，必须有人去用。**
   实测最坑的一次：kit 预留了 16% 的字幕带、description 里写着「词级字幕」，
   而全 kit **没有一行字幕代码** —— 于是每支片都少一层，底部还空着一条带子。
   **description 承诺的能力，必须有对应实现**，否则就是给自己挖坑。
4. **转场当作一条缝写，不是一格的收尾。**
   前一格盖上、后一格揭开，两半同一个 seed。只写单侧的话，揭开那一半在 0.4s 的缝里
   永远轮不到执行 —— 结果是涂满 → 硬切 → 空白。
5. **阈值要从实测反推，不要拍脑袋。**
   闷棍阈值一开始定 85%，实测发现涂鸦盖到 76% 时肉眼已经是闷棍了，才收到 60%。
   定完必须回头验：**在正常样本上零误报**才算数。
6. **skill 本身别绑模型，但软链要一个个挂。**
   skill 是一堆 markdown + 纯 node 脚本 + 浏览器里跑的 JS，本来就跟哪家模型无关 ——
   实测同一份 SKILL.md 用 `deepseek-v4-flash` 跑，四道闸和字幕契约都能准确复述。
   **真正会漏的是安装**：这台机器上 skill 的真身在 `~/.agents/skills/`，
   CodeBuddy 从 `~/.codebuddy/skills/` 软链过去，而 handdrawn 当初只挂进了
   `~/.claude/skills/` —— 换执行器一跑，agent 压根找不到这个 skill，
   于是自己瞎编画风（v1 就是这么翻的车，用了 PingFang + feTurbulence 冒充手绘）。
   新 skill 落地后，**三个目录各挂一次并逐个 `md5` 验一遍**读到的是不是同一份。

## 写工单时的对应条款

工单模板在 `app.js` 的 `buildDesignPrompt()`，第 4–5 条是两道闸，第 12–17 条是上面这些规矩的落地。
改规矩要两处一起改：**skill 管「怎么做」，工单管「这次必须做」** ——
执行方不一定通读 skill 的每一节，但工单它一定从头读到尾。
