# 无露脸 TTS：动作接力，而不是滚动页面

这条分支用于用户明确要求无露脸、已获授权的 TTS 配音。当前 Director CLI 的 `prepare/compose` 不接受独立音频源；作者需编写带本地 `<audio class="clip">` 的 HyperFrames HTML 工程。以下是创作约定，不是新增 CLI schema 或自动生成能力。

## 画面减到必要内容

竖屏可采用浅灰外底、四周留边的白色内画布与柔和阴影。主体、必要的短手写文案、稳定字幕构成画面。默认移除常驻品牌、期号、装饰分割线、页脚、进度条、重复卡框和解释性小字。每一时刻有一个清晰主角；标题不能把字幕再重复一遍。

使用 `assets/doodle/icons/` 的 Oreo 原始 SVG 与克制配色。保留第三方文件的原始 path 和许可，通过容器位移、缩放、旋转或遮罩表现动作，不能只在素材目录里放图标、成片却看不到。图标用于解释“谁在做什么、导致什么”，不以图标墙或资产目录作为无关片头。不要将整页滚动、所有图标同步摆动或大量装饰线条当成手绘动感。

## 先设计变化，再选择 easing

每个主要动作先回答四件事：动作前是什么状态，谁改变了什么，为什么改变，动作后怎样影响下一步。用稳定对象 id 保存这个过程；跨段时让同一张记录、同一个任务或同一个容器继续参与。

例如：“记录 → 整理 → 分享”应让同一批记录陆续进入画面、聚拢为一份笔记，再由这份笔记发出；不是三张互不相关的静态插图依次淡入。公开 [无声动作研究](../examples/motion-study/README.md) 展示了可编辑 HTML 的做法，没有接入用户语音。

| 动作环节 | 编排依据 |
| --- | --- |
| 起步 | 在对应旁白锚点附近给出明确变化，不让观众等待整段结束才看到动作 |
| 移动或变形 | 用短而可感知的加减速；路径与尺度变化服务于关系和视线 |
| 落位 | 减速收住；仅在表达材质或反馈时使用轻微回弹 |
| 接力 | 相关对象错峰行动，上一动作收尾时下一动作开始，避免整组齐进齐出 |
| 理解 | 允许必要的稳定停留，字幕保持可读；不强制相机或每个物件一直动 |

镜头可以稳定。只有需要揭示关系、切换焦点或调整构图时才移动；没有“全片相机非零速度”规则。把长画布从头到尾向上推，或者只把 `ease: 'none'` 换成缓动函数，都不能替代物件动作设计。图解也不必每句换页，同一关系可跨多个字幕延续。

照片和截图仍是图像素材，可以局部放大、圈画、遮罩揭示并衔接到下一动作；只有具备分层素材并适合内容时才拆分前景与背景。不得把普通图片包进 SVG 就宣称矢量画质提升。

## 声画锚点与可复现时间轴

先使用实测音频或已有转录确定旁白与字幕时间，再为完整意思安排动作。为每段保留“开始/结束时间、实际旁白、核心意思、主对象 id、状态前后、动作锚点”的对照记录；这是作者的审查表，不是 Director 新增的字段。

新增片头、重排分段、改变语速之后，重新逐段核对：讲“记录”时正在记录，讲“整理”时正在整理，不能让一整段画面落后于声音。关键词只用于定位，不用逐词配图代替理解。字幕、音频和主要动作使用同一时间基准，不以字数等分伪造对齐。

每个 composition 注册一条 `paused`、有限时长的 GSAP timeline。动作、遮罩、描线和镜头都由该时间轴驱动。不要使用无限 CSS/SMIL、墙钟动画、随机数或渲染时的在线素材。重复 seek 同一时间应得到相同状态。

## 先小样，再全片

1. 新动作风格先渲染 10–15 秒，覆盖一次完整因果变化和跨段交接。正常速度观看并核对配音；用户要求先确认时，先交小样等待确认。
2. `hyperframes check --snapshots --json` 的错误应修复，布局警告逐项处理。检查标题、字幕、对象轨迹和过渡期间的重叠。
3. 全片检查开头、每个语义锚点、边界前后和最后一秒。观察主对象是否接得上，动作是否齐步走，是否有突然清空、跳位或无内容等待。
4. `python3 tools/check-frame-motion.py film.mp4 --boundaries 6.5,14.9` 可辅助定位重复帧、低变化区间和边界附近的像素变化。默认只输出诊断；明确需要技术阈值时才指定 `--max-freeze-seconds`。它不能判断动作有没有意义、加减速是否自然，也不能证明声画对齐或排除 PPT 感。背景漂移、微小摆动也能产生变化；必要的阅读停留则可能产生重复帧。两者都需人工判断。
5. 以正常速度观看成片并听声音，分别记录技术检查、视觉判断和声画核对的结果。无声研究不能算 TTS 同步验收，数值通过不能写成审美通过。
