## 一、静默失效类（最贵——它不报错，只是不对）

### 1. `<script src>` 引在 `<template>` 外不执行

HyperFrames 的子合成包在 `<template>` 里。引在外面的脚本永远不跑，而且**没有任何报错**，只是 `HW is not defined`。

→ hw-kit / rough.js / gsap 的 `<script>` 必须写在 `<template>` **内**。

### 2. 运行时会抹掉帧根元素的 `id`

它把 `id` 换成 `data-hf-authored-id`。所以 `document.querySelector("#frame-root")` 返回 `null`，`gsap.set("#frame-root", ...)` 变成一句安静的空操作。

→ 用 `HW.el()` 拿根元素。

### 3. GSAP 会**替换**SVG 的 transform，不是叠加

三种中招姿势：
- 在 path 上写 translate → 被 boil 抹掉
- 给正在 boil 的元素做位移 → 每帧被覆盖
- 给承载静态定位的元素做位移 → 定位丢了

→ 三层结构解决：`anchor`（静态定位）→ `mover`（编排器动这层）→ `path`（boil 动这层）。动东西一律 `HW.host(el)`。

### 4. 建了却没交给编排器的形状，会在 t=0 完整显形

因为它从没被「画出来」，所以一直是完成态。三位数的里程表长出第四条分隔线就是这么来的。

→ 形状默认 `opacity: 0` + `__hwPending`；`HW.draw` / `HW.pop` 等会认领它。跑 `HW.audit(S)` 查漏。

### 5. rough.js 的 `solid` 填充会隐形

kit 给所有 path 强制 `fill: none`（其他填充样式都需要），但 solid 填充是个**填充多边形**，被这条规矩杀掉了。

→ mkPath 里对 `fillStyle === "solid"` 单独走一支。

### 6. 多笔画共享 `rot` 会把自己转散架

`S.add([shaft, head], { rot })` 时每笔画各建各的 anchor，**各绕各的中心转**——箭头杆转了、箭头尖没转，飘在一边。循环图三个箭头看着像三根没头的弧就是这个。

→ `add` 对数组统一按并集中心重新设 pivot。

## 二、测量类（数字是对的，量错了东西）

### 7. `getBoundingClientRect` 包含动画 transform

`wordsIn` 建卡时就把每个词停在 y+14。用 rect API 量，标注会低 14px，缩放预览下还会错比例。

→ `rectOf` 走布局几何（`offsetLeft/offsetTop`），对 transform 免疫。

### 8. 量 div 的盒子 ≠ 量字

一个不可断的长词会横向溢出盒子，而盒子照报它的固定宽度——宽高两项都过，适配器于是认为一切正常。324px 的 "Shape" 比装它的框宽 153px 就是这么过关的。

→ `S.textExtent` 用 Range / 子元素并集量真实字形。

### 9. `glyphBand` 的 `h` 是**单行 cap 高度**，不是整块高度

它是给圈注 / 删除线贴合用的。拿它去问「装得下吗」，五行的块会被当成一行放行。

→ 要判断装不装得下用 `fullH`。`textExtent` 已经改用 `fullH`。

### 10. 适配必须在**拆词之后**跑

每个词是 `inline-block`，**inline-block 不能在中间断行**。`scenes-index` 当纯文本时浏览器乐意在连字符处断成两行，拆成 span 后它变成一个刚性块——于是适配批准的字号，渲染出来是四行。

→ `words()` 先拆 span 再适配。量的必须是真正要渲染的那个布局。

### 11. 文字适配跑在字体加载之前 = 全错

按 fallback 字体算的字号，Excalifont 一到就重排，然后溢出。

→ 建卡包在 `document.fonts.ready` 里。

### 12. 审计里的缩放快照会过期

画幅切换时网格正在重排，用一次性快照的缩放系数去换算，2px 的抖动会被放大成 265px 的幻影越界。

→ `auditMotion` 每个采样点现取 `rect` 和 `k`。

## 三、几何类

### 13. 旋转默认绕 anchor 原点（左上角），不是形状中心

歪几度的便签，远角会甩出它的槽位。

→ mkPath 里用 `mover.getBBox()` 算中心再 `rotate(deg, cx, cy)`。

### 14. `HW.gear` / `HW.magnifier` 收的是**半径**，`bulb` / `stickman` 收的是**整体尺寸**

传错 = 画成两倍大。icon-row-doodle 里齿轮曾经溢出 98px。

→ 一排图标要先归一化再画（见那张卡的注释）。

### 15. 滑开 / 翻转的行程必须夹进安全区

`door-open-reveal` 的门要滑自己一个身位才能让开，只有门宽 ≤ 安全区一半时才有这个余量。`box-unpack` 的盖子扫过一个自己宽度的四分之一圆，**在哪边铰接决定它出不出画**。

→ 行程 = `min(自身宽, 那一侧的余量)`；盖子选余量大的一侧铰接，再把角度往回收到整个扫掠多边形都在里面。

### 16. 入场起始态也算越界

sticky 的 `scale 1.14` 拍入、ladder 的滑入偏移，**在 t=0 那一刻就在安全区外**。

→ sticky 按 `cell/OVER` 画，峰值刚好等于格子；ladder 的升起量夹进剩余空间。

## 四、环境类

### 17. Chrome 自动翻译会改写已经量好的文字

它在建卡测量之后替换 span 内容，于是圈注错位；换进来的字还在字体子集之外，触发 fallback 字体。

症状：截图上的字和卡里写的**对不上**（「不 二 邻近的 镜头 重复」vs 卡里的「相邻两镜不许重样」）。

→ 每个文字元素 `translate="no"` + `.notranslate`，页面加 notranslate meta。

### 18. 中文必须按本片字符重新子集化

playground 里的 Xiaolai 子集是 GB2312 常用 6796 字。**成片要按自己的稿子重新子集**，否则要么缺字要么白扛 21MB。

### 19. `</script>` 出现在被内联的 JS 注释里会截断脚本块

一句注释里写了 `</script>`，整个内联块提前结束，后面全是 `HW is not defined`。

→ 内联时转义成 `<\/script`。

### 20. Puppeteer 的 console 类型是 `"warn"` 不是 `"warning"`

过滤错了会让你以为审计没跑。（这条是我自己踩的。）

## 五、动效尺度（三条硬判据）

来自 MotionSet 384 份真实生产 prompt 的词频统计——**与风格无关，什么风格都得过**。

1. **元素动作 300–500ms 是主力**；>600ms 的占比 ≤25%，超了要能说出它凭什么慢。
2. **错峰 60–100ms**：<45ms 人眼读不出先后（做了等于没做），>140ms 拖节奏。
3. **blur 和 scale 同级用**（真实词频 970:1068）。只有位置在变、清晰度不变，画面就是硬的。
4. 进 `expo.out` / 出 `power3.in` / 位移 `power4.inOut`。**每个元素都要有进有出**，不是进场后杵着。
5. GSAP 核心版**不解析 `cubic-bezier()` 字符串**，写了会静默退化成线性 → 只用内置缓动名。
6. boil 幅度 `amp 0.5–0.6` / `rot 0.12–0.18` / `frameDrop 4`——再大会抖，再小会死。用默认值即可。

`node scripts/motion-lint.mjs <片目录>` 查 1–5 条。

## 六、版面与验收类

这一组的共性：**它们都不报错，只是做出来的片子不对**，而且要到人肉看成片才发现。
四轮下来累计烧掉约两小时，其中大部分是「为了看一眼而先渲一遍」。

### 24. kit 预留了字幕带，却没有任何字幕实现

`CAPTION_RESERVE` 只被拿去把 SAFE 缩短，全 kit 搜不到一个字幕渲染器 ——
而 SKILL.md 的 description 白纸黑字写着「词级手绘字幕」。

后果是双重的：每支片都少一层字幕，**而且底部那条带子一直空着**，
于是画面看着重心坠底。人会以为是构图问题，其实是缺了一层。

→ 现在有 `HW.captions()` / `HW.wrapZh()`。
→ 更通用的教训：**description 承诺的能力必须有对应实现**，否则就是给自己挖坑。

### 25. `S.safe` 只管「别出界」，不管「别坠底」

把落版字放在 safe 的最下沿是**完全合法**的。实测就这么翻车：
落版格重心落在画面 **70%**，上方 53% 全空，读起来像掉下去了。

→ 用 `S.hero`（重心 30%–58%）。竖屏的光学中心比几何中心高，在 38%–45%。
→ `gate.mjs` 的画面审计会检出，别只靠肉眼。

### 26. 只往 hero 里放一个主体 → 画面从中间断成两截

主体挤在 30%–58%、字幕在 75%–86%，中间 58%–75% 系统性地空着。
实测：单主体块的格连续空带 29%/33%，铺了支撑层的格只有 7%–22%。

这跟「疏」不是一回事 —— 墨覆盖 1%–3% 是这个风格的正常值，疏是风格，**断层是缺陷**。

→ 每格至少两层：主视觉 + 支撑层。**补一层信息，不要放大主体**（放大只会让它更孤立）。

### 27. 转场只写单侧，揭开那一半永远轮不到执行

`scribble-wipe` 的旧 recipe 是 `draw` 在 0–0.42s、`opacity:0` 在 0.5s，
可整条缝只有 0.44s。实测后果：4.30s 整幅涂满（墨覆盖 76%，一记闷棍）→
4.50s 硬切全白 → 4.90s 下一格才画第一笔，**缝里连续四张纯白帧**。

→ 转场是**一条缝**，两半分开写：前一格盖上、后一格揭开，两半同一个 SEED。
→ 缝里任意时刻画面上都得有东西，不许出现纯白或纯黑帧。

### 28. `S.add` 默认 `opacity:0`，纸色道具在纸面片里等于隐形

「揭开」那一半画上去也是白的 —— 你以为道具没生效，其实是它跟纸一个颜色，
或者根本还没被 `HW.claim` 点亮。

→ 揭开半程要显式 `gsap.set(HW.host(x), { opacity: 1 })` 起手。

### 29. 转场 recipe 里硬编码 `1920, 1080`

竖屏片是 1080×1920，**长宽是反的**，带子只盖得住上半截。
而 kit 自己的注释就写着 "nothing downstream may hardcode a pixel"。

→ 一律走 `S.frame.w` / `S.frame.h`。

### 30. `命令 | tail -N` 让没过的闸看起来过了

拿到的是 tail 的退出码，永远 0。执行方于是「报完成」，而闸实际是 1。
**报喜不报忧比直接失败更贵**，因为你以为过了，直到最后才发现。

→ 判闸一律看退出码本身；跑 `gate.mjs`，它内部用 `spawnSync` 拿真实 status，
   并把结论写进 `design/_gate/verdict.json`。

### 31. 验收排在渲染后面 —— 这一条比上面所有加起来都贵

`hyperframes snapshot` 吃的是**工程目录，不是视频**。建完帧就能抓图，不必先渲。
可默认流程是「建全部格 → 渲整片 → 抓中点 → 才看见不对」。

→ 先验后渲。方法论见 `tools/README.md`。

## 七 · 闸看不见的那两类

这支片四道闸**首跑全过**，但人眼一看仍有两处不对 —— 说明闸判的是构图和空带，
不判「两个元素挨得对不对」和「这一帧该不该已经写完」。这两类只能靠看拼版。

### 32. 引线 / 连接线的位置写成固定比例，会被长短不一的文字穿过去

一行「事项 ——— 时长」的账，引线起点拍了个 `r.w * 0.40`。
二字的「写稿」好好的，四字的「对时间轴」就被引线从中间穿了过去。
闸不会报：墨还是那些墨，重心没变，空带没变。

→ **凡是「挨着某段文字放」的东西，起点从量出来的字宽算**：
   `var ng = S.glyphBand(nm.items); var lx = ng.x + ng.w + mk * 0.55;`
   槽位（slot）给的是**可以放多宽**，不是**实际占了多宽**。

### 33. 支撑层排在 85% 采样点之后写完 —— 闸抓到的是一句写了一半的话

画面审计只在每格 85% 那一帧判构图。一格 6.924s，采样点是 5.885s；
支撑层排在 5.52s、逐字 0.045s 步进 12 个字，写完要到 6.375s。
于是拼版上永远是「没过就自己修，不」。

→ **一格里所有该被看见的东西，都要在 `DUR * 0.85` 之前落定。**
   写完的时刻 = `at + (字数 - 1) * step + dur`，排完自己乘一遍。
   收尾的转场（`DUR - 0.4` 上下）不受这条约束，那时候画面本来就该在变。

### 34. 闸接错了 lint —— 它一直在空过，而且报的是 ✓

`gate.mjs` 调的是 `motion-quality/scripts/motion-lint.mjs`。那个脚本**只从
`tools/`（文件名要匹配 `build-frames|frames?.`）和 `src/` 里找 `.mjs/.js/.ts/.tsx`**。
videohand 的帧是 `compositions/frames/*.html` —— 它一条都读不到，于是打印
「blur 0 处 / 缝 0 条」，然后 `exit 0`。

判据①②实际是**零样本**，闸照样打勾。实测：闸连报两次「motion-lint 退出码 0」，
而 videohand 自带的 motion-lint 在同一批帧里抓出两处 30ms / 40ms 的错峰。

**零样本不等于通过。** 一个闸如果可能因为「没找到东西可查」而返回 0，
它就必须把样本数打出来，让人能看见「查了 0 条」。

→ `gate.mjs` 现在同时跑 videohand 自带的 `scene-lint` / `motion-lint`
   （它们直接读 `STORYBOARD.md` 和 `compositions/frames/*.html`）。
   通用那个留着，但它不再是唯一的动效闸。

→ 连带的第二个盲点：videohand 的 motion-lint 用正则 `(?:stagger|step):\s*([\d.]+)`
   抓错峰值，**只认字面量**。写成 `step: L.cmd ? 0.030 : 0.012` 它看不见。
   算出来的值不等于查过了 —— 该写注释说清楚为什么这个值是对的。

## 八 · 合成之后才发作的坑

下面五条是同一次事故拆出来的。共同点：**它们全都只在"子合成被合进主合成之后"才发作**，
而当时四道闸都在合成之前看，playground 和单帧预览也都只有一个帧在场 ——
于是一支画面全灭的片子拿着五个绿勾渲了出来。

现在由 `scripts/portability-lint.mjs` 专门查这一类（第五道闸）。

### 35. CSS 变量落空 → **所有手绘笔画变透明**

帧里写的是 `#frame-root { --hw-ink: … }`，可根元素其实叫 `id="root"`。
选择器一条都不命中，浏览器不报错，整段样式静默作废。

后果不是"颜色不对"，是画面全灭：rough.js 把颜色写成 SVG 呈现属性（不解析 `var()`），
kit 因此改走 `style.stroke = "var(--hw-ink)"`；变量没定义 → 解析失败 → 描边为 `none`。
**笔画一条都看不见，只剩 DOM 文字活着**，看起来像"这一版就是极简风"。
同一条也让 `font-family: var(--hw-font-print)` 落空，中文掉回系统宋体。

三路探针（把三种画法并排画进同一帧）一次定位：

| 画法 | 结果 |
|---|---|
| 手写 path + 硬编码 `#c00` | 可见 |
| 手写 path + `style.stroke = "var(--hw-ink)"` | **不可见** |
| rough.js 画的线 + 硬编码 hex | 可见 |
| 运行时探测 | `rough=object`、`kitPaths=21`、`inkVar=""` |

21 条 path 一直好好地在 DOM 里，只是没有颜色。**"什么都没画出来"和"画了但看不见"
是两件完全不同的事**，先分清再修，否则会去查 rough.js 有没有加载（它一直是好的）。

→ 配色的真源搬进 JS（`HW.PALETTE`），`HW.stage` 开场把它**内联写到根元素上**。
   内联样式不受任何选择器重写影响，在 hyperframes / Studio / iframe / playground /
   别人家的渲染器里一律成立。外部 CSS 仍可覆盖：读得到就用读到的。

→ 帧里的选择器仍然只能是 `#root`。挂 class 也不行 —— 渲染时每条规则被 scope 成
   `[data-composition-id="…"] <选择器>`，以根自己的 class 起头会变成一条匹配不到根的
   后代选择器。`#root` 被 scoper 特判，是唯一安全的写法。

### 36. 七个帧抢同一个 `#root` → 全片叠成一坨

脚手架教的是根用 `id="root"`。合成之后七个子合成的 DOM 同时挂在一个 document 里，
于是页面上有七个 `#root`，`document.querySelector("#root")` 永远返回**第一个**。
后面六帧的笔画全画进第一帧的画布：转场盖子从第 0 秒糊到最后，主体互相压。

**单帧预览永远看不出来** —— 那时页面上确实只有一个 `#root`。
hyperframes 自己的规矩写在 SKILL 里：*每个 id 必须在合成后的整页里唯一*。

→ `HW.stage` 要收本帧的合成 id：

```js
var S = HW.stage("#root", { w: 1080, h: 1920, id: "03-visualize" });
HW.frame(tl, S, DUR);        // 收 stage，不收选择器
```

`data-composition-id` 按定义整页唯一，是唯一可靠的身份。漏传且页面上有重名时
`HW.stage` 直接抛错 —— **静默拿第一个才是灾难**，报错只是麻烦。

### 37. 揭示门用 raw `gsap.set` → 抓帧和拖动都会看到未来

`HW.draw` 以前在建帧当下就 `gsap.set(el, { opacity: 1 })`，全靠
`strokeDashoffset = len` 把形状藏住。可粗圆头笔触在虚线相位上会漏成一串圆点，
整块转场涂抹于是提前显形。

补救办法本来写在 `hw-trans.js` 的 `X.D` 里，SKILL.md 还专门叮嘱"别直接用 HW.draw"。
**但靠人记得绕开默认路径的规矩，迟早会被忘掉** —— 一支片七帧全忘了。

→ 闸挪进 `HW.draw` 本身，默认就是安全的；`X.D` 保留只为兼容。
→ 用 `tl.fromTo(..., { immediateRender: true })`，不要 `tl.set()`。
  raw set 只在建帧那一刻跑一次、**不可回滚**：时间轴被直接 seek 到某个时刻
  （抓帧、快照、Studio 拖动）时不会退回去，于是看到本该在未来才出现的画面。

### 38. 建帧里抛一个异常 = 那一格在成片里是一整段纯白

`S.below(chain.slots[last], …)` 传的是槽位矩形而不是元素，`rectOf` 掉进 DOM 分支，
`el.getBoundingClientRect is not a function`。异常发生在建帧 IIFE 里，
**整帧就此中断**：那一格什么都没有，前面已经建好的形状也一个都不会动。

四道闸没有一道看得见 —— 它们都只读源码，不读运行时。
`hyperframes check` 的 **Runtime** 段看得见，一句 `console_error` 指名道姓。

→ `S.boundsOf` 现在认矩形（槽位本来就是矩形，卡片这么传天经地义）。
→ **渲染前必须看 `check` 的 Runtime 段**，别只看总的退出码。

### 39. gsap 引 CDN → 断网 / CI / 别人的机器上是白屏

帧里写 `<script src="https://cdn.jsdelivr.net/npm/gsap@3.14.2/…">`。
本机联网时一切正常，所以能一路过闸；换台机器、进 CI、或者网络到不了 jsdelivr，
就是白屏，而且版本会在你不知道的时候变，确定性渲染直接失效。

同一族的还有资产路径带 `../`：渲染会按子合成源文件路径重写所以跑得动，
**Studio 预览和别的消费方按项目根解析 → 404**。"在我这儿好好的"就是这么来的。

→ 一律 `assets/vendor/` 本地副本 + 根相对路径。第五道闸查这两条。

### 40. 同一个 skill 在本机有两份，其中一份带着已经修好的 bug

`~/.claude/skills/videohand` 是仓库（已修好），`~/.workbuddy/skills/videohand` 是**实体拷贝**，
还是坏的那一版。目录结构、文件名、大部分内容一模一样，
**唯一的差别要渲一支片出来才看得见**。

同一个病还有更常犯的第二种：**每支片会把 `assets/` 复制进片目录**。
改完 skill 的引擎不同步过去，重渲毫无变化 —— 人会以为"没修好"，
回头去改本来已经对的代码。今天就绕了很久：改完 kit 的第一次重渲一点变化都没有，
因为片子读的是它自己那份三小时前的拷贝。

→ **"坏了就删"防不住，因为你看不出它坏了。** 能防住的是让每一份必须能自证版本：

| 规矩 | 谁来查 |
|---|---|
| skill 目录里只允许有 git 仓库，不允许有实体拷贝（仓库能 `git log`，拷贝不能） | `tools/doctor.mjs` 的副本盘点 |
| 每支片带的 `assets/` 必须跟 skill 那份逐字节一致 | `portability-lint` 第四条 |

→ 比对**按内容哈希**，不靠版本号。版本号要人记得 bump，而人不会记得。
   片子从来不该改引擎，所以"不一样"＝"旧了"，不需要判断谁新。
   `HW.VERSION` 只是让人和日志读得懂。
